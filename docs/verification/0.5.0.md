# Development build verification — 0.5.0-dev

Date: 2026-11-16. Package `org.eightbit.bite`, versionCode **6**, minSdk 28,
compile/targetSdk 36. Built with JDK 17 and Gradle 8.13 on Linux using the normal
Android Gradle Plugin resource, compilation, DEX and packaging pipeline.

## Changes verified

- The profile-photo tab contains the combined diary, trends and supplements.
  Water, supplement and trend cards can collapse; settings can hide the optional
  sections. Settings uses the top-right gear; AI has a bottom navigation tab.
- Water entries persist by date, support custom ml/L servings and undo/deletion,
  and continue recording above the chosen target. A 2,000 ml target with a 100 ml
  serving produces 20 glasses. Servings of 700 ml or more use bottles.
- Food favourites persist separately from the catalogue and support a filtered
  saved-food list. The last selected meal is retained between additions.
- The meal editor's supplement checkbox writes one diary entry and one associated
  supplement intake in a transaction. Editing, retrying and toggling it preserve
  this relationship without counting food nutrition twice. Legacy scoop units,
  product targets and intake history are retained.
- Protein, carbohydrate and fat goals are off by default and enabled separately.
  Protein-powder mass and creatine have separate optional targets. Stored profile
  fields include age, weight, height, sex and the calorie target.
- The app offers English, Turkish, German, French, Spanish, Italian, Portuguese
  and Japanese. Each has 308 translated app strings plus eight widget strings.
  Product names, provider responses and external model metadata retain their
  original wording. English and Japanese dashboard components were rendered
  and visually inspected with Robolectric's native graphics mode.
- Existing avatar selection, AI camera/review, API-key and downloaded local-model
  paths, background model downloads, widgets and the seven-version-tap theme
  unlock remain in the source. The original watermelon icon is unchanged.

## Data preservation

The private Room database advances from schema 1 to 2 with an explicit migration;
there is no destructive fallback. Migration tests start with the exported schema
1, retain existing meal snapshots, NULL nutrients, supplement targets/history and
version state, and validate the resulting schema. Turkish uppercase supplement
names are included in the classification coverage.

The public food catalogue remains **0.4.0 / schema 1**, independent of the app and
private Room versions. It contains 2,193 foods, including 260 ETİ foods. Its
current and immutable copies, and the bytes packaged in the APK, match the
supplied SQLite file exactly. Catalogue integrity, required tables, unknown
nutrients, release metadata and absence of personal-data tables passed checks.

To repeat the project checks with Android SDK 36 and JDK 17 installed:

```sh
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
python3 scripts/check_catalogue.py
python3 -m unittest discover -s scripts -p 'test_*.py' -v
```

## Device and feature limits

No phone or emulator was connected. Real-device upgrade installation, camera,
launcher widgets, background scheduling, AI inference and Health Connect still
need device validation. This is a development-signed build, not a store release.

The water suggestion is an optional adult age/sex starting reference with an
explicit food-water assumption, described in `docs/HYDRATION.md`. It does not
predict an individual's needs from weight, height, calories or supplement grams,
and never overwrites the user's target automatically. Water stays in the private
app database in this release; Health Connect export continues to cover nutrition.
No ChatGPT subscription login or subscription-funded API access is implemented.

The assumed GitHub repository has not been published. Remote update availability
is dependent on hosting its manifests and immutable catalogue snapshots; local
SQLite import continues to work independently.
